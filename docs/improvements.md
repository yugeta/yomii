# 改善点・課題一覧

```
Updated : 2026.04.30
```

## 概要

現時点でのコードベースを分析し、セキュリティ、パフォーマンス、コード品質、アーキテクチャの観点から改善点をまとめます。

---

## 1. セキュリティ

### 1.1 コマンドインジェクション（重大）

**対象:** `public/page/upload/php/pdf.php`, `public/page/upload/php/zip.php`

ユーザー入力由来の値（UUID、ファイルパス）がエスケープなしで `exec()` に渡されています。

```php
// pdf.php - 危険なパターン
$cmd = "pdftoppm -png {$pdf_file} {$out_path} -f {$page} -l {$page} -cropbox -singlefile";
exec($cmd);

// 削除処理
exec("rm -rf ".$this->setting["tmp_dir"] , $res);
```

**改善案:**
- `escapeshellarg()` でパラメータをエスケープする
- `tmp_dir` のパスをバリデーション（ホワイトリスト方式）してから使用する
- `rm -rf` の代わりに PHP の `rmdir()` / `unlink()` を使う

### 1.2 ファイルアップロードのバリデーション不足

**対象:** `public/page/upload/php/upload.php`

- アップロードファイルのMIMEタイプ検証がない
- ファイルサイズの上限チェックがPHP設定のみに依存
- ファイル名のサニタイズが不十分

**改善案:**
- `finfo_file()` でMIMEタイプを検証する
- 許可する拡張子のホワイトリストを実装する
- ファイル名にパストラバーサル文字が含まれていないか検証する

### 1.3 パストラバーサルの可能性

**対象:** `public/page/upload/php/common.php`

`uuid` パラメータに `../` が含まれた場合、意図しないディレクトリにアクセスされる可能性があります。

```php
public static function get_uuid_dir($uuid=null){
    $dir = dirname(__FILE__). "/../../../". Common::$temp . $uuid;
    return Common::normalize_path($dir);
}
```

**改善案:**
- UUIDの形式を正規表現で厳密にバリデーションする
- `realpath()` の結果が想定ディレクトリ配下であることを確認する

### 1.4 CSRF対策の欠如

**対象:** `public/book.php`

POSTリクエストにCSRFトークンの検証がありません。

**改善案:**
- セッションベースのCSRFトークンを実装する
- リクエストヘッダーの `Origin` / `Referer` を検証する

### 1.5 認証・認可の未実装

現状、すべてのAPIエンドポイントが認証なしでアクセス可能です。

**改善案:**
- Google OAuth2 認証の実装（README に記載あり、未実装）
- APIリクエストにセッション認証を追加する

## 2. パフォーマンス

### 2.1 変換データのBase64格納（メモリ効率）

**対象:** `public/page/upload/php/pdf.php`, `public/page/upload/php/zip.php`

全ページの画像をBase64エンコードして1つのJSONファイルに格納しています。100ページの書籍の場合、数百MBのJSONファイルが生成される可能性があります。

```php
$base64 = base64_encode(file_get_contents($webp_path));
$jsons[$i] = $base64;
// ... 全ページ分を1つのJSONに格納
```

**改善案:**
- 画像ファイルを個別に保存し、メタデータのみJSONに格納する
- ページ単位でのストリーミング読み込みに対応する
- ZIPアーカイブ形式（現在のクライアントサイド `.yomii` 形式）をサーバーサイドでも採用する

### 2.2 PHP max_execution_time の制約

**対象:** `docker/php/php.ini`

`max_execution_time = 30` ですが、大きなPDFの変換には数分かかる場合があります。バックグラウンド処理（CLI）では無制限ですが、設定の意図が不明確です。

**改善案:**
- CLI実行時の設定を明示的に分離する
- 変換処理のタイムアウト管理を実装する

### 2.3 フロントエンドの画像メモリ管理

**対象:** `public/page/book/js/zip.js`, `public/page/book/js/pdf.js`

全ページの画像を一度にメモリに保持しています。大きな書籍ではブラウザのメモリを圧迫します。

```javascript
// zip.js - 全画像をメモリに保持
this.images.push(img)
```

**改善案:**
- 表示中のページ周辺のみメモリに保持し、それ以外は解放する
- `URL.revokeObjectURL()` で不要なBlobURLを解放する
- Web Worker を使ったバックグラウンドデコードを検討する

### 2.4 Canvas の不要な再描画

**対象:** `public/page/book/js/view.js`

ページ遷移のたびに前後ページの Canvas を再生成していますが、既に描画済みかどうかのチェックが不完全です。

**改善案:**
- 描画済みページのキャッシュ管理を強化する
- 離れたページの Canvas を破棄してメモリを解放する

## 3. コード品質

### 3.1 コメントアウトされたコードの大量残存

**対象:** 多数のファイル（`event.js`, `book.js`, `__groups.js` 等）

使われていないコードがコメントアウトのまま残っており、可読性を下げています。

**改善案:**
- 不要なコメントアウトコードを削除する
- 必要な場合は Git の履歴で参照する

### 3.2 エラーハンドリングの不足

**対象:** フロントエンド全般

- `JSON.parse()` が try-catch なしで使用されている
- ファイル読み込みエラー時のユーザーへのフィードバックがない
- Promise の reject ハンドラが未実装の箇所がある

```javascript
// convert.js - エラー時の処理がない
const res = JSON.parse(e.target.response)
```

**改善案:**
- `JSON.parse()` を try-catch で囲む
- ユーザー向けのエラーメッセージ表示を実装する
- グローバルエラーハンドラを設置する

### 3.3 重複コード

**対象:** `pdf.php` と `zip.php`

`resize_image()` と `delete_tmp_dir()` が両ファイルでほぼ同一のコードとして存在しています。

**改善案:**
- 共通の基底クラスまたはトレイトに抽出する
- `Common` クラスに移動する

### 3.4 未使用の変数・未定義変数

**対象:** `public/page/upload/php/pdf.php`

```php
// $page が未定義
function webp2json($webp_path=null){
    $num = sprintf("%03d" , $page);  // $page は未定義
    ...
}
```

**改善案:**
- 静的解析ツール（PHPStan等）を導入する
- 未使用変数を削除する

### 3.5 `Dockerfile copy` の残存

**対象:** `docker/php/Dockerfile copy`

コピーファイルがそのまま残っています。

**改善案:**
- 不要であれば削除する
- 必要であれば適切な名前にリネームする

## 4. アーキテクチャ・設計

### 4.1 フロントエンドのモジュール管理

バンドラー（Webpack, Vite等）を使用せず、ブラウザネイティブのES Modulesのみで構成されています。

**現状の問題:**
- ミニファイ・バンドルされていないため、本番環境でのHTTPリクエスト数が多い
- Tree-shakingが効かない
- ポリフィルの管理が手動

**改善案:**
- Vite等のビルドツールを導入する（開発時はES Modules、本番はバンドル）
- ただし、現状の規模であればネイティブES Modulesのままでも許容範囲

### 4.2 状態管理の分散

**対象:** `data.js`, `common.js`, `element.js`

グローバル状態が複数のクラスに分散しており、データの流れが追いにくい。

**改善案:**
- 状態管理を `Data` クラスに一元化する（現状ほぼそうなっているが、一部 `Common` にも状態がある）
- イベント駆動のパターン（Observer/EventEmitter）を導入する

### 4.3 テストの欠如

ユニットテスト、E2Eテストが存在しません。

**改善案:**
- PHPUnit でバックエンドのテストを追加する
- Jest / Vitest でフロントエンドのユーティリティテストを追加する
- Playwright / Cypress でE2Eテストを追加する

### 4.4 環境設定の管理

環境固有の設定（ポート番号、パス等）がハードコードされています。

**改善案:**
- `.env` ファイルによる環境変数管理を導入する
- Docker Compose で環境変数を注入する

### 4.5 ログ管理

変換処理のログが `nohup.out` に出力されるのみで、構造化されていません。

**改善案:**
- 構造化ログ（JSON形式）を導入する
- ログレベル（INFO, WARN, ERROR）を実装する
- ログローテーションを設定する

## 5. UX・機能面

### 5.1 オフライン対応

現状、サーバーアクセスが必要です。

**改善案:**
- Service Worker を導入してオフライン閲覧に対応する
- IndexedDB に書籍データをキャッシュする

### 5.2 アクセシビリティ

- キーボードナビゲーションが未実装（左右キーでのページめくり等）
- ARIA属性が未設定
- スクリーンリーダー対応がない

**改善案:**
- キーボードショートカットを追加する（←→キー、スペースキー等）
- 適切なARIAラベルを設定する
- フォーカス管理を実装する

### 5.3 レスポンシブ対応の強化

画面回転時にリサイズイベントで再描画していますが、アニメーションがなく唐突に切り替わります。

**改善案:**
- 画面回転時のトランジションアニメーションを追加する
- ピンチズームに対応する

### 5.4 エラー状態のUI

ファイル読み込み失敗時やネットワークエラー時のUIフィードバックがありません。

**改善案:**
- エラー状態を表示するUIコンポーネントを追加する
- リトライ機能を実装する
